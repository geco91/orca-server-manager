{% elif name == 'providers' %}

The standard server image includes OpenCode. Initial setup selects it as the Orca host default when no agent has been chosen. No API key or provider account is created.

  1. Choose OpenCode in Orca. In the agent picker, right-click OpenCode and choose Set as default. Orca saves this WebUI preference separately for each browser.
  2. Add a model provider when needed. Open OpenCode in your workspace and use /connect to enter a provider key or follow its native sign-in. More providers can be added later.
  3. Start your first task in Orca. A prepared agent does not confirm that a provider is authenticated; this status check starts no agent task.

Open Orca WebUI & pairing →

Provider credentials follow OpenCode's native profile scope. Workspace-specific options and environment references belong in OpenCode's project configuration.

{% elif name == 'mcp' %}

The separate BuildContext community bridge exposes Orca's native CLI to external MCP coordinators.

This is the opposite direction to MCP servers used by Orca's own agents.

The runtime image includes the bridge. It starts only when its private token has been configured, using read-only status tools by default. The deployment guide describes enabling delegation when needed.

The status probe sends MCP initialize, tools/list and a read-only Orca health call. It does not launch an agent.
